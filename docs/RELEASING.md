# GitHub 发布步骤

本项目直接从 [Git 仓库](https://github.com/MrGuang123/dsh-theme-caishen) 安装，不需要发布到 npm。仓库须包含 `package.json`、`cordis.patch.yml`、已构建的 `lib/`、`assets/runtime/`、插件管理页图标与语言元数据，以及清单引用的配色参考。不要只上传截图或打包文件。源码、原稿和开发文档保留在仓库，运行包只携带安装所需内容。

这里列出的推送与发布命令由维护者确认后执行，不会自动上传内容。

## 首次公开前

1. 确认仓库可公开访问，并添加 `dsh-plugin` Topic。
2. 核对 `package.json` 的作者、仓库链接和 MIT 许可证元数据，以及仓库中的 `LICENSE`。
3. 确认 `package.json.version` 为准备发布的版本；`engines.dsh` 只填写已验证的版本范围。
4. 检查 README 截图可在仓库中直接打开。独立预览图保留其来源说明，实际安装截图注明对应 DSH 版本。
5. 检查暂存文件，不提交个人 profile、会话、密钥、缓存、系统杂项或临时预览输出。
6. 核对 [需求清单](REQUIREMENTS.md) 和 [实施计划](IMPLEMENTATION-PLAN.md)，发布说明只写本轮实际实现的项目；待实施功能和待验证实机结果不写成已完成。

GitHub 安装可以保留 `package.json` 中的 `private: true`；它阻止 npm 发布，不阻止从 Git 安装。

## 检查源码与打包内容

修改源码后先在仓库根目录运行：

```bash
npm run build
npm run check:release
npm pack --dry-run
npm pack
```

`npm run build` 从 `src/` 生成 `lib/client.js`、`lib/client.css`、`lib/host/*.js` 及 `lib/index.js`；提交时同时包含源码与产物，不直接修改 `lib/`。`check:release` 先验证产物与源码一致，再执行离线检查与打包检查；它不会自动重建。需要单独核对时运行 `npm run check:build`，该命令只检查、不写入文件。

发布前还应执行目标宿主 `npm run check:host -- /path/to/app.asar`，以及配置外部运行时后的 `npm run check:browser`，再完成真实打包安装；环境与命令见 [兼容说明](COMPATIBILITY.md)。这两项是显式外部验收，不伪装为日常零依赖离线检查。重复打包同版本时给验收包使用不同的路径/文件名，避免包管理器复用先前内容，并核对安装后 JS/CSS 哈希。

核对打包列表包含以下内容：

- `lib/` 中的客户端 JS、独立 CSS、宿主模块及入口。
- `cordis.patch.yml`、`locale/*.json`、`assets/application/plugin/icon.svg` 和 `reference/tokens.json`。
- `assets/runtime/` 中十六项当前及旧 URL 兼容素材，含无字场景。
- 根目录的包清单与说明文件，以及 npm 自动纳入的 `assets/README.md` 目录索引。

`src/`、`scripts/`、完整开发文档、PNG 原稿、历史素材、截图和 Dock 图标不进入运行包；Dock 图标在仓库中单独下载。README 的文档和图片使用仓库绝对链接，需核对目标分支与文件存在；它们不要求安装包携带截图。确认没有本机路径、个人配置或临时文件。打包检查还验证压缩包与展开后的体积预算，不应绕过白名单和预算来临时容纳资源。

`npm pack` 生成的 `.tgz` 是可供本机验收或 GitHub Release 附件使用的安装包；GitHub 仓库本身仍需提交源码与运行文件。不要将 `.tgz` 反复提交进 Git 历史。

## 全新环境验收

使用与日常工作隔离的 DSH 测试 profile / 测试环境，记录 DSH 完整版本、操作系统和运行方式。不要仅通过开发目录的链接安装判断发布完成。

先在「插件」→「添加插件」填入刚生成的 `.tgz` 的绝对路径，完成安装并启用，核对：

- 插件页能读到正确名称、版本、图标与介绍，没有加载错误。
- 浅色、深色及跟随系统能切换；新会话与已有消息的会话均能打开。
- 首页恢复带字书籍/电脑、原气泡与背景；图片功德及红金功德簿中线对齐；输入卡片右列财神完整可见，输入栏没有主题外观按钮；已有会话不显示首页横幅。
- `/theme-caishen/styles/client.css` 正常返回 CSS，界面样式完整；原 `/theme-caishen/assets/` 素材路径及 `/theme-caishen/extra/` 兼容别名可用。
- 「今日财运在线」在新旧会话中的高度一致，功德 `+1` 从文字位置上飘。
- 功德簿主动打开，累计/里程碑/每日趣味签有装饰说明，重置有确认；原生 Web Locks 的同来源双窗点击不丢失，配额失败的本地增量可重试，无锁明确仅本窗保留，关闭彩蛋保留计数。
- 两个同名项目按宿主稳定 ID 隔离；项目库初始空、全局旧库不变，收藏/最近使用、备份/导入、重置/恢复和撤销只作用于当前范围；无法取得身份时禁用项目选项，切换范围保护未保存内容。
- 提示词新增、修改、删除、八色选择与排序可用；刷新后保留，点击卡片只填入而不发送。
- 已有消息的会话可从输入区「提示词」打开完整库；标题/简介/正文搜索、标签分类、收藏与最近使用可用；首页最多六张，满 128 张仍能检索，关闭/填入恢复输入焦点。
- 正文复制、另存为不改写原卡片；变量模板明确启用、必填校验和最终预览可用，普通双花括号正文不受影响。旧数组与版本 1/2 备份兼容，变量模板标记可完整往返。
- 提示词库打开后修改草稿或切换会话，旧插入不能覆盖新内容；嵌套编辑/导入弹窗的 Esc 只关闭当前层。可选快捷键命令在宿主设置中分配，未绑定不占用按键。
- 非空输入插入失败时原文保留；编辑/排序有修改时关闭、Esc、遮罩与取消均需确认，继续编辑和放弃后的焦点合理；删除撤销保留全部字段与原位置。
- 「备份与导入」可下载 JSON、选择文件或粘贴、预览合并、二次确认替换；校验失败、超限、空列表、重复 ID、期间外部变化和保存失败均按说明处理。
- 在隔离测试数据中核对损坏/读取拒绝/配额错误：保留原文和当前草稿，普通写入不覆盖损坏值；显式重置先保存异常恢复副本，重载后仍可导出。
- 从宿主设置左侧「主题外观」进入内嵌表单，支持预览、保存、取消和默认，离开页面回滚未保存预览；插画/装饰/彩蛋、专注模式及三组强调色可用；预览不写入，取消释放 token 覆盖，切换模式不修改宿主浅深色偏好。
- 窄内容容器、窄窗口、低高度、英文和 200% 字号下，横幅同步收紧，主题入口不挤出权限/发送，编辑与设置弹窗可滚动到达主要按钮；错误有关联描述，减少动态效果关闭动画。
- 外观异常、配额和跨窗冲突不覆盖原数据，停用/卸载移除主题属性及覆盖层；卡片与功德计数不受外观开关影响。
- 关闭整个「财神打工版」组合包及卸载均正常，主题不再占据宿主界面插槽，插件添加的样式 link 已移除；按宿主要求刷新或重启后确认恢复。只关闭内层 `theme-caishen` 行不算完整停用，因为禁用官方品牌的补丁仍在组合包中。

验收结束后在 [验证记录](VALIDATION.md) 中填写实际结果；未完成的项目要明确标记，不写成已经通过。独立布局预览、组件对照和离线检查均不替代这一步。结构重构完成不代表已经完成新构建产物的真实 DSH 安装验收。

## 推送仓库与版本标签

确认工作区内容、版本号和验收结果后再提交。首次关联远端可使用：

```bash
git remote add origin https://github.com/MrGuang123/dsh-theme-caishen.git
git push -u origin main
```

如果已配置 `origin`，先核对现有地址，不重复添加。以上命令假设当前分支为 `main`，分支名称不同则使用实际名称。

发布 `0.2.0` 时，版本号与标签保持对应：

```bash
git tag -a v0.2.0 -m '财神打工版 v0.2.0'
git push origin v0.2.0
```

后续版本修改 `package.json.version`、发布记录和文档中的示例版本，再创建新标签；不要移动已经对外分享的标签。

## 验证 GitHub 安装后分享

在隔离的测试环境中，再使用公开地址安装一次：

```bash
dsh plugin --profile web add 'git+https://github.com/MrGuang123/dsh-theme-caishen.git#v0.2.0'
```

`web` 应替换为实际 CLI profile。桌面端用户建议在 DSH「插件」→「添加插件」填同一地址。确认下载、版本识别、启用和素材加载成功，再把带标签的地址分享给其他用户。

可在 GitHub 创建对应标签的 Release，写明功能、实际验证的 DSH 版本、已知问题和安装地址，并附上 `.tgz` 作为另一种安装来源。Release 不是 Git 安装的必要条件；标签和完整仓库内容才决定该地址安装的版本。

第三方插件升级通常需要卸载后重新安装新标签。发布说明应提醒用户先备份自定义提示词文本；本主题不会主动清理浏览器中的卡片数据，但更换访问地址、浏览器或清理网站数据会影响本地存储。
